gqteashmd

Automated surface-hopping molecular dynamics with PySCF.

Write one TOML input file and run one command. gqteashmd optimizes the molecule, computes its vibrational frequencies, samples initial geometries and velocities from the Wigner distribution, computes the vertical excitations, selects the initial excited states, runs the surface-hopping trajectories and turns them into state populations and an excited-state lifetime. The whole run resumes where it stopped after a crash, a reboot or a deliberate stop.

Get gqteashmd 0.1.0

Linux only. Free and open source, MIT license.

Release notes and earlier versions

What it does

One input file drives eight stages, from the geometry to the lifetime. Each stage is split into tasks that run in parallel, and every finished task is kept, so a run that stops resumes where it stopped.

A strict input file, checks before anything runs, and a run that can be stopped, resumed and changed safely.

  • One strict TOML input file; units in the key names (dt_fs, temperature_K); gqteashmd validate lists every problem at once
  • Checks before a run: the project location, free disk space, the required Python packages and the hardware you declared
  • Parallel tasks on one workstation, with cores, memory and threads set per stage
  • Crash-safe resume: a killed run, or one stopped by a clean restart, continues from its finished tasks and the last restart of each trajectory
  • gqteashmd stop and gqteashmd status; pauses for review after chosen stages (pause_after)
  • Change detection: a changed input never mixes with old results; --rerun-from STAGE says what to recompute
  • A provenance record of every run (versions, packages, machine) and, since 0.1.0, the commit of the installed build

The molecule's ground state at the level of theory of the dynamics.

  • prepare: checks and stores the molecule, its charge and multiplicity
  • optimize (optional): the S0 geometry with geomeTRIC
  • frequencies: the S0 Hessian, analytic for SCF methods or by finite differences for SA-CASSCF; normal modes and a Molden file
  • Electronic structure from PySCF: SCF, state-averaged CASSCF, TDA, TDDFT, CIS and TDHF; energies, analytic gradients and transition dipoles
  • A fixed start for SA-CASSCF: every fresh solve begins from a reference solution at the stage's reference geometry

Initial geometries, velocities and excited states for the trajectories.

  • sampling: harmonic Wigner sampling with exact thermal widths; linear and angular momentum removed; an exact energy check per mode
  • excitations: vertical excitation energies and oscillator strengths at every sample, and the absorption spectrum as a CSV file
  • selection: the initial state of every trajectory, by bright-state selection (weight f/dE² or f) in an energy window, or a fixed state
  • Reproducible: every random number derives from project.seed, so the same input gives the same samples, also after a restart

One surface-hopping trajectory per selected initial condition, each a resumable task.

  • SHARC-type or Tully (FSSH) hopping, with velocity adjustment and the energy-based decoherence correction
  • Couplings from wavefunction overlaps (local diabatization, every method) or SA-CASSCF nonadiabatic couplings
  • Step rejection: an unreliable step (a failed calculation, a small overlap, an energy jump, a changed CASSCF start) is redone with halved steps
  • A restart after every accepted step; an outcome for every trajectory (finished, energy drift, overlap or electronic failure, electronic discontinuity)
  • Raise tmax_fs and run again to extend the finished trajectories
  • An optional hop energy rule that keeps the previous step's total energy, as SHARC does (hop_energy = "previous")

From trajectories to populations and a lifetime, with uncertainties.

  • Classical and quantum state populations with 95 % intervals
  • The censored estimator by default: a trajectory that ended early still counts up to its end (Aalen-Johansen), and the complete-trajectory rule is reported beside it
  • A delayed mono-exponential fit (delay t0 and lifetime tau) with bootstrap intervals
  • Hop statistics, first arrival in S0, energy drift and energy-jump diagnostics
  • A warning below 50 trajectories: in a synthetic test, the 95 % lifetime interval reached 90 % coverage from 50 trajectories on
  • Results as CSV, HDF5, JSON and a Markdown report

One input file, one command

The input on the right is the real input of the 100-trajectory ethylene ensemble shown on this page. Everything not written in it takes its documented default (the populations figure below was computed with the complete-trajectory rule, estimator = "complete", not today's default). gqteashmd run input.toml then runs every stage to the end.

  • Survives crashes. Kill the run or restart the machine, run the same command again: finished tasks are kept and every trajectory continues from its last restart, which is safe against a killed process, not against a power cut.
  • Stops when asked. gqteashmd stop ends a run gracefully, and pause_after stops it after a stage you want to check first.
  • Never mixes old and new. Each stage records a fingerprint of its inputs. A changed input stops the run and names the --rerun-from stage that recomputes what it affects.
  • Records what ran. Every run appends the program version, the commit of the installed build, the Python packages and the machine to provenance.json.

dynamics and analysis stages

Dynamics that run to the end, or say why they stopped

Every trajectory is its own task with its own restart. At every step the program checks the new electronic structure before it accepts the step, and when a trajectory cannot go on it ends with an outcome that says why, instead of producing numbers nobody can trust.

  • Overlaps every step. Wavefunction overlaps between consecutive steps carry the state couplings and track the states through crossings.
  • Rejected, then halved. A step with a failed calculation, a small overlap, an energy jump or a changed CASSCF start is redone as two half steps, down to an eighth of the step.
  • Honest outcomes. Finished, energy drift, overlap failure, electronic failure or electronic discontinuity, each with its time and its message.
  • Lost trajectories still count. The default censored estimator uses an early-ended trajectory up to its end; the complete-trajectory rule is reported beside it.

Known limitations

  • Closed-shell singlets only: no triplets or spin-orbit coupling from PySCF (they exist only for the analytic and LVC models of model-dynamics). Linux only, on one workstation, without a batch scheduler.
  • 33 of the 100 ethylene trajectories end early after a hop, when the CASSCF calculation switches to another solution.
  • The lifetime is uncertain: the censored estimate is 62 fs and the complete-trajectory estimate 80 fs. The measured back-hop rates on these data argue against the censored estimator's assumption, so its shorter lifetime is not shown to be unbiased, and which value is closer to the truth is not known.
  • The comparison with SHARC's own electronic-structure interface is inconclusive; a replayed trajectory disagrees with SHARC after its hop under the default hop energy rule (with hop_energy = "previous" it agrees over the 20 steps after the hop); the lifetime fit has not been compared with SHARC's make_fit.py.
  • No plots: the results come as CSV, HDF5, JSON and Markdown files.

Install

  1. Download the release

    From the latest release, download environment.lock.txt and the wheel, gqteashmd-0.1.0-py3-none-any.whl.

  2. Create the environment

    In a Linux shell: conda create -n gqteashmd-0.1.0 --file environment.lock.txt, then conda activate gqteashmd-0.1.0. The lock file gives the exact packages the release was tested with.

  3. Install the program

    pip install --no-deps gqteashmd-0.1.0-py3-none-any.whl. Check it with gqteashmd --version, which names the version and the commit it was built from.

  4. Run a project

    gqteashmd init input.toml writes a commented template. Edit it, check it with gqteashmd validate input.toml, then start it with gqteashmd run input.toml.

Requirements

  • Linux, 64-bit. Tested on Oracle Linux 9.5 under WSL2.
  • conda (for example Miniforge). PySCF, NumPy, SciPy, h5py, geomeTRIC and pydantic all come from the lock file.
  • On Windows, use WSL2, and keep projects on the Linux filesystem, not under /mnt/c or a OneDrive folder.
  • SHARC 4.1 and ORCA are needed only for the comparison tests, not to run gqteashmd.
Install for development instead

From a clone of the repository, in WSL or Linux:

git clone https://github.com/AdemirCamargo57/gqteaSHMD.git
cd gqteaSHMD
conda env create -f environment.yml
conda activate gqteashmd-dev
pip install -e . --no-deps
