# CLAUDE.md — gqteashmd

`gqteashmd` is our own surface-hopping molecular dynamics (SH-MD) program. It automates the SHARC-style workflow:

```text
optimize → frequencies → Wigner sampling → initial conditions → trajectories → analysis
```

The user writes one TOML input file and runs `gqteashmd run input.toml`. The program then runs every stage to completion, survives crashes and restarts, and resumes where it stopped. Electronic structure comes from PySCF only (first release). The program runs on Linux only: an Oracle Linux 9 workstation, with no batch scheduler.

- **Keep project runs, conda environments and large outputs out of OneDrive and out of `/mnt/c`.** Use `~/...` or `/tmp` in WSL. pytest's `tmp_path` already does this.
- **Workflow.** Feature branch per sub-project (`feat/<topic>`), one commit per task, conventional commit subjects (`feat:`, `fix:`, `test:`, `docs:`, `ci:`, `build:`). The owner decides merges. P1, P2, P3a, P3b, P3c, P4, P5, P6, P7a-1, P7a-2, P7b, P8 and P9a are merged into `main`; `main` is on GitHub (`AdemirCamargo57/gqteaSHMD`) up to P8 (pushed on 2026-11-12, merge commit `1185ac1`); the P9a merge (`99c2062`, 2026-11-13) is local and not pushed. Merged feature branches are deleted.
- **Seeds (D12).** Every random stream derives from `project.seed`: `util/seeds.py:task_rng(project_seed, stage_name, task_index)` is `default_rng(SeedSequence([project.seed, zlib.crc32(stage_name)]).spawn(i + 1)[i])`, so it does not depend on the number of tasks or on other stages. **Samples are reproducible from the input** (same input, same `samples.h5`, also after a crash and restart). A stage that draws random numbers must hash `project.seed` in its fingerprint and must use `task_rng`, never a global generator. **P6:** `selection` draws from `task_rng(seed, "selection", 0)`, one `random()` per candidate; `trajectories.json` records trajectory k's future dynamics stream as `rng: {"stage": "dynamics", "task_index": k}`, not as an integer seed. **P8:** `analysis` draws its bootstrap resamples once from `task_rng(seed, "analysis", 0)` (`integers(0, N, size=(B, N))`, reused for the quantum intervals and the fit) and hashes `project.seed`.
- **Commit trailer.** End each commit message with the `Co-Authored-By:` trailer for the model that wrote the commit.
- **Keep the two documents current.** Update **CLAUDE.md and USER_MANUAL.md in the same branch as any change to behaviour, inputs, outputs, formulas or status.** USER_MANUAL.md must always mark what is implemented and what is planned.

- **Stage contract** (`stages/base.py`):
  - `plan(ctx)` runs in the controller and returns `TaskSpec` objects deterministically.
  - `run_task(ctx, task, task_dir)` runs in a worker subprocess. It must be idempotent, write only in `task_dir`, and return a small JSON-serialisable dict.
  - `finalize(ctx, results)` runs in the controller, writes the stage artifacts and raises `StageFailedError` if checks fail.
  - Stage attributes: `name`, `version`, `depends_on`, `config_sections`, `required_modules` (checked by preflight), `max_failed_fraction`, `enabled(config)`, `check_config(config)` (P6, see P6 modules), `reopen_tasks(ctx, results)` (P7b, default `[]`; see the P7b block and the orchestrator rules).
- **Worker protocol** (`worker.py`): the worker reads `task.json` and writes `result.json` atomically, either `{"status": "ok", "result": ...}` or `{"status": "error", "error_type", "message", "retryable", "traceback"?}`. Errors are also written to stderr, which goes to `worker.log`. A worker that exits without `result.json` is treated as a crash, which is retryable. An unreadable or malformed `task.json` gives a non-retryable error result (`Cannot read task file …`, `ProjectError`) written next to it; a non-serialisable result (`TypeError`/`ValueError`) is reported the same way. `write_bytes_atomic` removes its temp file if the write fails. Workers read the config snapshot `.gqteashmd/config.json` and never the user's input file.
- **P4 stage rules:**
  - `optimize` uses **one backend for the whole path** (successive geometries reuse orbitals); the finite-difference tasks of `frequencies` each build a **fresh backend**, so orbital reuse cannot bias the Hessian. Both take S0 settings from `ground_state_settings`. With CASSCF, `optimize`'s first geometry and every `frequencies` task start from the reference solution of the start rule (each `frequencies` task searches its own reference at the same working geometry; in Task 5, 20 independent searches in separate workers gave SA energies within 2.0e-13 Eh).
  - Hessian by finite differences: `H[:, k] = (g(R + h e_k) - g(R - h e_k)) / (2h)`, then `(H + H^T)/2`; `1 + 6N` gradient tasks.
  - `frequencies.finalize` writes `frequencies.h5/.molden/.json` first, then raises `StageFailedError` if any `nu < -imaginary_cutoff_cm1`. Warnings (logged and in `frequencies.json`): small imaginary modes, external residual > 100 cm^-1 (replaces the master plan's near-zero-mode stop; measured 22-41 cm^-1 at optimized geometries), max |gradient| > 1e-3 Eh/bohr.
  - `optimize` non-convergence is a non-retryable `TaskError` with advice; `optimization_path.xyz` and `best.xyz` (lowest energy, not the last geometry) stay in the task directory. One atom: outputs are written without calling geomeTRIC; `frequencies` of one atom has 0 modes.
  - **Fingerprints (S0-relevant only):** `OptimizeStage` and `FrequenciesStage` hash `electronic.factory.ground_state_fingerprint` (the S0 settings without `td_conv_tol`, `overlap_norm_kept` and, for non-CASSCF methods, `singlets`; for CASSCF plus `start_rule = CASSCF_START_RULE` since the start rule) plus their own section; `frequencies` also drops `imaginary_cutoff_cm1` (a finalize-only check). A new stage must hash only what changes its results; keys read only by `finalize` are left out (`frequencies.imaginary_cutoff_cm1`; `excitations.max_failed_fraction`, `broadening_fwhm_eV`, `spectrum_step_eV`; `selection.allow_fewer`, and `selection.weighting` in fixed mode), so changing them repeats only the finalization. Every piece of advice that tells the user to change a hashed key must name the `--rerun-from` stage it needs.
  - **Linearity (`vib/harmonic.py`):** from the principal moments of the mass-weighted, centred coordinates, linear when `I_min/I_max < LINEAR_INERTIA_RATIO = 1e-3`; the rotation about the near-molecular axis is dropped (5 external vectors), an atom has 3. No rank threshold. `linear` and `n_external` are attributes of `frequencies.h5`.
  - **FD consistency (`frequencies.finalize`):** every FD task returns its energy; `max_k |(E+ - E-)/2h - g_ref,k|` must be <= `FD_CONSISTENCY_TOLERANCE = 1e-4` Eh/bohr, and when the geometry comes from `optimize`, `|E_ref - optimize.json energy|` <= `OPTIMIZED_ENERGY_TOLERANCE = 1e-6` Eh; otherwise `StageFailedError` (only `frequencies.json` is written, with the measured values). Measured: water 2.8e-6, ethylene SA-CASSCF(2,2)/STO-3G 4.6e-6 Eh/bohr.
- **Executor** (`execution/local.py`):
  - one subprocess per task, each in its own session;
  - the orchestrator builds **one executor per stage** from that stage's effective resources (`ResourcesSection.for_stage(name)`: a `[resources.stages.<name>]` key, or the global value if unset);
  - at most `max_parallel_tasks` running at once;
  - sets `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS` and `MKL_NUM_THREADS` to `threads_per_task`, and `PYSCF_MAX_MEMORY` to `memory_mb_per_task`;
  - on stop: SIGTERM to the process group, SIGKILL after `stop_grace_period_s`;
  - **whole-group kills:** a worker's process group also gets SIGKILL after the leader exits normally, on a stop, and in `terminate_process_group(pid, grace)`, so children that stay in the worker's process group are killed while the controller runs (children that call setsid/setpgid, and strays of a worker that finished while the controller was dead, are not); the stop grace period applies to the leader only;
  - if a callback raises, it reaps every worker before re-raising.
- **Orchestrator rules** (`orchestrator.py`, spec §3.4):
  - **`Orchestrator.session()`** (context manager, re-entrant): collects the provenance record, takes the project lock, then calls `layout.ensure()` and removes stale `.<name>.tmp` files from `.gqteashmd/` (left by a crashed controller). `run()` and `cli._cmd_run` both use it, so **one session = one run = one provenance record**, and the lock comes before `ensure()` and before logging. A run refused by the lock creates only `.gqteashmd/` (for the lock file) and writes no log and no provenance.
  - **Deleted stage directory:** any stage that is not SKIPPED and is DONE, or has DONE tasks, but whose results directory is missing, is reset (`state.reset_stage`) and recomputed, with a warning; its fingerprint is unchanged. (P3c covered DONE stages only.)
  - **Fingerprint:** SHA-256 over the stage name, version, `fingerprint_inputs()` and the upstream fingerprints. A DONE stage with the same fingerprint is skipped.
  - **`fingerprint_inputs` reads no upstream artifacts** (P4 rule, documented in `stages/base.py`): the controller also calls it before any stage has run, with an empty `ctx.upstream`. Stages depend on upstream results only through `depends_on` (their fingerprints are chained in).
  - **Stale pre-pass (P4):** `Orchestrator._check_up_to_date` computes all fingerprints and raises `StaleStageError` **before** the config snapshot is written, a `--rerun-from` reset or any stage record is touched, so a refused run leaves `config.json` byte-identical and the stage records unchanged. The provenance record is still appended (documented). Stages from the `--rerun-from` stage on are exempt.
  - **Optional stages (P4):** a disabled stage gets the fingerprint `"skipped"` for its dependants. If it already has results (DONE or DONE tasks), its record is kept (not overwritten with SKIPPED); a dependant that was computed from it is then stale (exit 3, e.g. disabling `optimize` after `frequencies` ran). Re-enabling it with unchanged inputs makes it and its dependants up to date.
  - **Changed fingerprint:** a stage that is DONE or RUNNING, **or that has any DONE task**, raises `StaleStageError`, which tells the user to run `--rerun-from STAGE`. Only stages with no finished task are reset automatically.
  - **`--rerun-from`:** moves the old stage directories to `.gqteashmd/superseded/`, never deleting them. It first terminates orphaned workers.
  - **Retries:** a crash or a retryable error is retried while `attempts < max_attempts`. An interrupted task is not counted as an attempt.
  - **Stage failure:** a stage fails when `failed/total > max_failed_fraction`. Any exception inside a stage marks it FAILED.
  - **Restart:** tasks left RUNNING by a dead controller are reconciled. A task with an ok `result.json` becomes DONE; otherwise its orphan is killed (verified via `/proc/<pid>/cmdline`) and the task is requeued.
  - **`--rerun-from`** is applied once per orchestrator (`self.rerun_from` is cleared after use). The hint printed for a stale stage is shell-quoted. A fingerprint input that is not JSON-serializable raises `ProjectError`.
  - **Reopening (P7b, O16):** for a DONE stage with an unchanged fingerprint whose class overrides `Stage.reopen_tasks` (`type(stage).reopen_tasks is not Stage.reopen_tasks`; other stages' up-to-date path is unchanged and reads no results), the orchestrator reads the DONE tasks' recorded results, calls the hook, and for a non-empty list **first marks the stage RUNNING (same fingerprint)**, then sets those tasks PENDING, runs the stage and finalizes again (`state.requeue_failed(stage)` also requeues tolerated FAILED tasks with attempts reset). **Every other existing record of a hook stage except SKIPPED (RUNNING, PENDING, FAILED) has the hook applied before `_run_stage`** (final fix wave I1: RUNNING = a controller killed part-way, possibly through a reopening, the hook being deterministic on the DONE results; PENDING = a user stop; FAILED = a stage failure), so a stop followed by a raised `tmax_fs` ends, in one run, with every `finished` trajectory at the new end (before the fix: DONE with 2.0, 2.0 and 3.0 fs); the stale-fingerprint check still comes first. Reopening does **not** change the fingerprint. A reopened stage in `pause_after` pauses again.
  - **Dependants of a reopened stage (P8, spec section 9; `_reset_dependants`, called by `_reopen`):** when the hook returns a non-empty list for stage X (any path: DONE, RUNNING, PENDING, FAILED), the orchestrator **first** resets every later stage that depends on X directly or transitively (`depends_on` closure) **and has results** (`_has_results`: DONE, RUNNING or any DONE task), enabled or disabled with a kept record: `_reset_stage` (orphans terminated, directory moved to `.gqteashmd/superseded/`, `state.reset_stage`), with the warning `Stage <name> is recomputed because <X> was extended`; **then** X is marked RUNNING (same fingerprint) and its tasks requeued (the P7b path). Kill-safe: after the reset and before the RUNNING mark, X is unchanged, the deterministic hook returns the same list and the dependants have no results. No fingerprint changes; the stale pre-pass and `--rerun-from` are unchanged; raising `tmax_fs` stays a plain `run`. A dependant without results, or skipped without a kept record, is left alone. This resolved the P7b deferral "a staleness rule for the dependants of a reopened `dynamics` stage". `AnalysisStage` also overrides the hook (ruling P8-3, P8 block), so it is read on every run.
  - **Pause (P7b ruling A):** a stage pauses only if a **later stage is enabled** (the documented "the last stage never pauses"); `dynamics` is enabled only with a `[dynamics]` table, so `pause_after = ["selection"]` pauses before the dynamics with the table and has no effect without it. Tested both ways (`tests/stages/test_dynamics_pipeline.py`). **P8:** `analysis` is now the last stage of `default_pipeline`, so `pause_after = ["dynamics"]` pauses before the analysis (no effect with `[analysis] enabled = false`); tested in `tests/stages/test_analysis_pipeline.py`.
  - **Pause:** after a stage listed in `workflow.pause_after` completes **in this run** and is not the last stage, `RunSummary.paused_after` is set, the loop stops and the CLI prints a message and exits 5 (`EXIT_STOPPED`). A rerun continues, because that stage is then up to date. A skipped or up-to-date stage never pauses. Unknown names in `pause_after` and in `[resources.stages]` are a `ConfigError` raised by `check_stage_names` (`stages/pipeline.py`), which both `Orchestrator.__init__` and `validate` call. `check_stage_inputs` (also in `stages/pipeline.py`, called by `validate` and `Orchestrator.__init__`) raises a `ConfigError` for every **enabled** stage whose `config_sections` entry is `None` in the config (e.g. `[electronic]`; `Stage 'optimize' needs an [electronic] section ...`, all joined by `; `).
- **Config** (`config/schema.py`): `[resources]` requires `total_cores` and `total_memory_mb`. A model validator checks `max_parallel_tasks × threads_per_task ≤ total_cores` and `max_parallel_tasks × memory_mb_per_task ≤ total_memory_mb` for the global values and for every stage override (merged with the global values); the message shows the factors (`3 × 2 = 6 exceeds total_cores = 4`). The keys of `[resources.stages]` must be safe stage names (`is_safe_name`). `execution.min_free_disk_mb` (default 1000) and `[workflow] pause_after` also live here. `loader.py` expands `~` (an unknown `~user` is a `ConfigError`) and resolves relative paths against the input file's directory. `[electronic]` (`ElectronicSection`, with the optional `CasscfSection` as `[electronic.casscf]`) is in the schema since P3a: `method` casscf|tda|tddft, `basis`, `functional` (required for tda/tddft, forbidden for casscf; `"hf"` gives CIS/TDHF), `singlets` (**includes S0**, O19), `triplets` (must be 0), `grid_level` (3), `scf_conv_tol`, `scf_max_cycle`, `td_conv_tol`, `overlap_norm_kept` (0.9999, 0.9 < x <= 1); casscf: `ncas`, `nelecas` (even, <= 2 ncas), `conv_tol`, `conv_tol_grad`. ## Key decisions (full list in master plan §10)
- **Python core.** Electronic structure dominates the cost, so the core is plain Python (D1).
- **PySCF only first.** PySCF is the only backend in the first release; ORCA, Gaussian, OpenMolcas and OpenQP come later behind the same backend contract (D4).
- **Single workstation.** The resumable controller runs one subprocess per task, with no scheduler (D5).
- **Strict input file.** One strict TOML input. Units go in key names (`dt_fs`, `temperature_K`, ...), and state labels are `S0`, `S1`, `T1` (0-based internally) (D7, D13).
- **Hardware from the user.** The user enters the hardware in `[resources]`. The program warns, without stopping, when the values exceed the detected machine (D17, implemented in P2).
- **Naming.** The package and command are `gqteashmd`; internal class names keep the `Shmd` prefix (D18).
- **P3 validation target.** Ethylene (`C:\AJCamargo\TOPICOS\Eteno\Eteno.xyz` → `tests/data/ethylene.xyz`) at SA2-CASSCF(2,2)/6-31G\* first, then TDA (D19). Done in P3a: it matches SHARC 4.1 to 1.4e-8 Eh (energies) and 1.4e-8 Eh/bohr (gradients), the dipole to 4.5e-7 e a0 up to sign; finite-difference gradient checks 1.8e-7 (CASSCF) and 5.7e-8 (TDA-B3LYP, grid_level 5) Eh/bohr.
- **O18 resolved:** `pyscf=2.14.*` pinned in `environment.yml`; runtime `pyscf>=2.6`. **O19 resolved:** `singlets` includes S0 (owner decision 2026-11-07).
- **O5 resolved (P4):** most-abundant-isotope masses in amu (`chem/masses.py`, H-Rn); reduced masses in the Gaussian/PySCF convention `mu = 1/sum(l^2/m)` (H2 stretch 1.0078 amu, not m/2). P5 sampling must use the same masses.
- **O4 resolved (P5, owner decisions 2026-11-08):** (1) T > 0 uses the exact harmonic thermal Wigner function, `sigma_Q^2 = coth(w/2kT)/(2w)`, `sigma_P^2 = w coth(w/2kT)/2` (hbar = 1, a.u.), which is the ground-state distribution at T = 0. (2) Modes with `nu < low_frequency_cutoff_cm1` (default 10 cm^-1, must be > 0), including the small imaginary modes kept by `frequencies`, are not sampled (equilibrium coordinate, zero velocity) and are listed in a warning and in `samples.json`. Linear and angular momentum are removed at each sample without rescaling. SHARC's `Ekin` line in `initconds` is the kinetic energy *before* its momentum removal (differs from the energy of its printed velocities by up to 6.4e-4 Eh), so compare pre-with-pre and post-with-post.
- **O3 and O20 resolved (P6, owner decisions 2026-11-08):** (1) bright selection accepts a candidate with probability `w/w_max` (w_max over the candidates, the window applied first and inclusive), with `weighting = "f_over_dE2"` (default; SHARC `excite.py`-compatible, **measured** in the P6 final fix wave by maximum likelihood on SHARC's black-box per-pair selections, `w = f^a dE^k`: k = -1.989 ± 0.050 (constant f = 0.1, dE ~ U(2, 10) eV, N = 3000, 598 selected), a = 0.993 ± 0.028 (constant dE = 5 eV, f ~ U(0.01, 0.4), 1527 selected); the window maximum, not the all-pairs maximum, normalises (SHARC [370, 699] vs f/dE^2 window-max z = (+1.19, +2.36), all-pairs max z = (+22.4, +32.8)); ours [353, 666], KS p = 0.96) or `"f"`; no paper is cited for f/dE^2.
