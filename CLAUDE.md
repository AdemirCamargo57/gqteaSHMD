# CLAUDE.md — gqteashmd

`gqteashmd` is our own surface-hopping molecular dynamics (SH-MD) program. It automates the SHARC-style workflow:

```text
optimize → frequencies → Wigner sampling → initial conditions → trajectories → analysis
```

The user writes one TOML input file and runs `gqteashmd run input.toml`. The program then runs every stage to completion, survives crashes and restarts, and resumes where it stopped. Electronic structure comes from PySCF only (first release). The program runs on Linux only: an Oracle Linux 9 workstation, with no batch scheduler.

## Architecture (implemented in P1, P2, P3a, P3b, P3c, P4, P5, P6, P7a-1 and P7a-2)
Dependencies point down only; domain code never imports stages or the orchestrator.

```text
cli.py ─► orchestrator.Orchestrator ─► execution.local.LocalExecutor (one per stage) ─► subprocess: python -m gqteashmd.worker task.json
   │         │  preflight.py (before the project directory is touched)       worker ─► stage.run_task() ─► result.json
   │         │  project/state.py (SQLite, single writer), project/provenance.py
   │         │  project/layout.py, project/lock.py (flock, taken first)
   │         └► stages/ (Stage contract: plan → run_task → finalize) ─► chem/, core/, util/, electronic/, vib/, excite/, geomopt, (later) dynamics/
   ├► single-point command ─► electronic.factory.make_backend ─► electronic.pyscf_backend.PySCFBackend (no project, no stages)
   ├► model-dynamics command ─► config.model_dynamics ─► dynamics.ensemble.run_model_ensemble (Tully) | run_population_ensemble (LVC, P7a-2) ─► dynamics.driver (no project, no PySCF)
   └► logging_setup.py (console INFO, logs/gqteashmd.log DEBUG)

tools/sharc_compare/   executes SHARC 4.1 as a black box (never imported by gqteashmd; P6: sharc_formats.py, run_excite.py, run_sharc_pyscf.py:run_geometry; P7a-2: run_sharc_lvc.py, lvc_ensembles.py, qmout.py extended, run_sharc_model.py:run_in_session/sharc_environment); tests in tests/sharc_compare, tests/validation, pytest -m sharc
```

- **P7a-1 rules (dynamics core):**
  - **Step order (plan Method reference 8; USER_MANUAL.md section 8.12; the P7a-2 form for U not `None` or `eselect_Eh` is in the P7a-2 block and reduces to this one):** (1) `q' = q + v dt + a dt^2/2`; (2) evaluate at `q'`; (3) `v' = v + (a - g'_lambda/m) dt/2` with the **old** active state; (4) propagate `c`; (5) hopping probabilities and the random draw; (6) hop: velocity adjustment of `v'` at fixed `q'` (frustrated: keep/reflect), then `lambda <- j`; (7) decoherence with `K` from the final `v'`; (8) `a'` from the new active gradient (recomputed from the snapshot, not stored); (9) record and drift check. The hop comes **after** the velocity completion, so `E_tot` is continuous across hops. Changing this order needs a new measurement against SHARC.
  - **Exactly one uniform random number per nuclear step**, used or not (also `hopping = "none"`), logged in `StepRecord.random_number` and stored in the restart. Ensemble trajectory `i` uses `default_rng(SeedSequence([seed, crc32(b"model-dynamics")]).spawn(i + 1)[i])`; initial conditions use `crc32(b"model-initial")`. Counts must not depend on `workers`.
  - **Restart is bit-identical** (50 + save/load + 50 = 100 steps, both schemes, EDC, hops present). It stores q, v, c, the snapshot, time, step, active, E_tot(0) and the RNG state; **not** masses, model parameters or options. **P7a-2 resolved the U part: the state carries U and restart format 2 stores it with the snapshot overlaps (see the P7a-2 block).** No model fingerprint yet (P7b).
  - **Workers spawn guard:** `workers > 1` uses a `ProcessPoolExecutor` with the explicit `spawn` context; model and options must be picklable and a calling script needs the `__main__` guard; all workers are joined also on an error.
  - Invalid options are `ValueError` naming the option (CLI: `ConfigError`, exit 2; a `ValueError` raised inside a trajectory is exit 1 with its own message); physical endings are outcomes, not exceptions. `parallel_vel` with `K = 0` and a downward hop raises `ValueError` (unreachable in practice).
  - **Defaults mix conventions on purpose:** `edc_convention = "sharc"` (SHARC 4.1 manual 8.7.1 eq. 8.25, damping at half the Granucci-Persico rate; measured kappa 0.500) but `substep_interpolation = "midpoint"` (second order; SHARC's manual scheme is `"endpoint"`, first order). The SHARC comparison uses `"endpoint"`.

Dynamics should still request overlaps every step, because it needs them. Phases are applied to the stored expansion, NACs (`p_I p_J d_IJ`) and dipoles (`p_0 p_I mu`). PySCF's raw CI signs are **not reproducible** across processes; phased output is reproducible only relative to a snapshot.
  - **Truncation keeps the union** over states of each state's important determinants (`overlap_norm_kept`, default 0.9999); a per-state cut destroys the couplings. NAC pairs are I < J. `compute_more` reuses the live PySCF objects of the last successful `compute` (error before it, after `load_state` and after a failed `compute`, which clears them). Errors inside truncation/overlap/tracking become `ElectronicStructureError` (non-retryable; `MemoryError` retryable).
  - **Overlap memory model:** `state_overlaps` never forms the n_det x n_det matrix. Each state is scattered onto an (N_alpha_unique x N_beta_unique) matrix and contracted with the two determinant tables, so memory is O(N_alpha_uniq*N_beta_uniq) per state; it estimates the bytes first and raises `MemoryError` above `MAX_OVERLAP_BYTES` (2 GiB). It takes an optional `s_mo_beta` for future unrestricted references.
  - Ladders: CASSCF (previous orbitals, SCF orbitals, SCF + spin penalty) and TD (default, extra roots); scratch: no chkfile, `pyscf.lib.param.TMPDIR` set to `scratch_dir` only during calls.
  - NACs exist for CASSCF only (`capabilities.nacs`); TDA/TDDFT use overlaps, built from X only (Y dropped, renormalised).
  - SCF ladder: default, then level shift 0.2 Eh + damping 0.5, then second-order. Only rung 1 starts from the previous geometry's density.
  - SA-CASSCF uses a **singlet-only CI solver** (`fci.solver(mol, singlet=True)`) with equal weights `1/N`, and a **spin guard**: `|<S^2>| > 1e-3` for any root is an error. The solver excludes triplets but not higher spins (quintets can appear in larger active spaces), which is why the guard exists. SCF ladder rung 2 sets `diis_start_cycle = 8`, because PySCF damps only before DIIS starts.
  - **Orbitals are reused between calls of one backend object only via `mcscf.project_init_guess`.** Never pass old MOs directly: they are not orthonormal at a new geometry.
  - Transition dipoles: CASSCF `-sum r_pq gamma^{0I}_pq` (active orbitals, `trans_rdm1`); linear response as returned by PySCF `td.transition_dipole()` (length gauge, no sign change). Their overall sign is arbitrary, so compare up to sign.
  - **Error mapping:** user input errors are `ConfigError` (exit 2: missing PySCF or version < 2.6, multiplicity != 1, charge/multiplicity vs electron count, missing `[electronic]`). The PySCF calls that run SCF, CASSCF, TD, gradients, dipoles and orbital projection are wrapped by `pyscf_errors.wrap_failure` into `ElectronicStructureError` (a `TaskError`, exit 4: unknown basis, SCF/CASSCF/TD non-convergence, spin, active space, gradient/dipole failures). It is non-retryable, except that `MemoryError` and `OSError` raised inside PySCF give `retryable=True` (transient I/O and out-of-memory are retried, spec §6.1). Do not let a raw PySCF exception escape from those steps. Config-level `singlets` is checked against the CAS singlet space (Weyl count) when the input is loaded.
  - `ground_state_hessian(coords_bohr)` (P4): analytic RHF/RKS Hessian from a fresh SCF (`Capabilities.hessian`, false for casscf; casscf raises `ValueError`). `factory.ground_state_settings(settings)` gives the S0 settings: SCF methods (tda/tddft) get `singlets = 1`, SA-CASSCF keeps its state average because that defines S0.
  - Not implemented: triplets/SOC, open-shell, density fitting, TDDFT NACs, a scratch key in the input file.
- **Stage contract** (`stages/base.py`):
  - `plan(ctx)` runs in the controller and returns `TaskSpec` objects deterministically.
  - `run_task(ctx, task, task_dir)` runs in a worker subprocess. It must be idempotent, write only in `task_dir`, and return a small JSON-serialisable dict.
  - `finalize(ctx, results)` runs in the controller, writes the stage artifacts and raises `StageFailedError` if checks fail.
  - Stage attributes: `name`, `version`, `depends_on`, `config_sections`, `required_modules` (checked by preflight), `max_failed_fraction`, `enabled(config)`, `check_config(config)` (P6, see P6 modules).
- **Worker protocol** (`worker.py`): the worker reads `task.json` and writes `result.json` atomically, either `{"status": "ok", "result": ...}` or `{"status": "error", "error_type", "message", "retryable", "traceback"?}`. Errors are also written to stderr, which goes to `worker.log`. A worker that exits without `result.json` is treated as a crash, which is retryable. An unreadable or malformed `task.json` gives a non-retryable error result (`Cannot read task file …`, `ProjectError`) written next to it; a non-serialisable result (`TypeError`/`ValueError`) is reported the same way. `write_bytes_atomic` removes its temp file if the write fails. Workers read the config snapshot `.gqteashmd/config.json` and never the user's input file.
- **P4 stage rules:**
  - `optimize` uses **one backend for the whole path** (successive geometries reuse orbitals); the finite-difference tasks of `frequencies` each build a **fresh backend**, so orbital reuse cannot bias the Hessian. Both take S0 settings from `ground_state_settings`.
  - Hessian by finite differences: `H[:, k] = (g(R + h e_k) - g(R - h e_k)) / (2h)`, then `(H + H^T)/2`; `1 + 6N` gradient tasks.
  - `frequencies.finalize` writes `frequencies.h5/.molden/.json` first, then raises `StageFailedError` if any `nu < -imaginary_cutoff_cm1`. Warnings (logged and in `frequencies.json`): small imaginary modes, external residual > 100 cm^-1 (replaces the master plan's near-zero-mode stop; measured 22-41 cm^-1 at optimized geometries), max |gradient| > 1e-3 Eh/bohr.
  - `optimize` non-convergence is a non-retryable `TaskError` with advice; `optimization_path.xyz` and `best.xyz` (lowest energy, not the last geometry) stay in the task directory. One atom: outputs are written without calling geomeTRIC; `frequencies` of one atom has 0 modes.
  - **Fingerprints (S0-relevant only):** `OptimizeStage` and `FrequenciesStage` hash `electronic.factory.ground_state_fingerprint` (the S0 settings without `td_conv_tol`, `overlap_norm_kept` and, for non-CASSCF methods, `singlets`) plus their own section; `frequencies` also drops `imaginary_cutoff_cm1` (a finalize-only check). A new stage must hash only what changes its results; keys read only by `finalize` are left out (`frequencies.imaginary_cutoff_cm1`; `excitations.max_failed_fraction`, `broadening_fwhm_eV`, `spectrum_step_eV`; `selection.allow_fewer`, and `selection.weighting` in fixed mode), so changing them repeats only the finalization. Every piece of advice that tells the user to change a hashed key must name the `--rerun-from` stage it needs.
  - **Linearity (`vib/harmonic.py`):** from the principal moments of the mass-weighted, centred coordinates, linear when `I_min/I_max < LINEAR_INERTIA_RATIO = 1e-3`; the rotation about the near-molecular axis is dropped (5 external vectors), an atom has 3. No rank threshold. `linear` and `n_external` are attributes of `frequencies.h5`.
  - **FD consistency (`frequencies.finalize`):** every FD task returns its energy; `max_k |(E+ - E-)/2h - g_ref,k|` must be <= `FD_CONSISTENCY_TOLERANCE = 1e-4` Eh/bohr, and when the geometry comes from `optimize`, `|E_ref - optimize.json energy|` <= `OPTIMIZED_ENERGY_TOLERANCE = 1e-6` Eh; otherwise `StageFailedError` (only `frequencies.json` is written, with the measured values). Measured: water 2.8e-6, ethylene SA-CASSCF(2,2)/STO-3G 4.6e-6 Eh/bohr.
- **Executor** (`execution/local.py`):
  - one subprocess per task, each in its own session;
  - the orchestrator builds **one executor per stage** from that stage's effective resources (`ResourcesSection.for_stage(name)`: a `[resources.stages.<name>]` key, or the global value if unset);
  - at most `max_parallel_tasks` running at once;
  - sets `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS` and `MKL_NUM_THREADS` to `threads_per_task`, and `PYSCF_MAX_MEMORY` to `memory_mb_per_task`;
  - on stop: SIGTERM to the process group, SIGKILL after `stop_grace_period_s`;
  - **whole-group kills:** a worker's process group also gets SIGKILL after the leader exits normally, on a stop, and in `terminate_process_group(pid, grace)`, so children that stay in the worker's process group are killed while the controller runs (children that call setsid/setpgid, and strays of a worker that finished while the controller was dead, are not); the stop grace period applies to the leader only;
  - if a callback raises, it reaps every worker before re-raising.
- **Orchestrator rules** (`orchestrator.py`, spec §3.4):
  - **`Orchestrator.session()`** (context manager, re-entrant): collects the provenance record, takes the project lock, then calls `layout.ensure()` and removes stale `.<name>.tmp` files from `.gqteashmd/` (left by a crashed controller). `run()` and `cli._cmd_run` both use it, so **one session = one run = one provenance record**, and the lock comes before `ensure()` and before logging. A run refused by the lock creates only `.gqteashmd/` (for the lock file) and writes no log and no provenance.
  - **Deleted stage directory:** any stage that is not SKIPPED and is DONE, or has DONE tasks, but whose results directory is missing, is reset (`state.reset_stage`) and recomputed, with a warning; its fingerprint is unchanged. (P3c covered DONE stages only.)
  - **Fingerprint:** SHA-256 over the stage name, version, `fingerprint_inputs()` and the upstream fingerprints. A DONE stage with the same fingerprint is skipped.
  - **`fingerprint_inputs` reads no upstream artifacts** (P4 rule, documented in `stages/base.py`): the controller also calls it before any stage has run, with an empty `ctx.upstream`. Stages depend on upstream results only through `depends_on` (their fingerprints are chained in).
  - **Stale pre-pass (P4):** `Orchestrator._check_up_to_date` computes all fingerprints and raises `StaleStageError` **before** the config snapshot is written, a `--rerun-from` reset or any stage record is touched, so a refused run leaves `config.json` byte-identical and the stage records unchanged. The provenance record is still appended (documented). Stages from the `--rerun-from` stage on are exempt.
  - **Optional stages (P4):** a disabled stage gets the fingerprint `"skipped"` for its dependants. If it already has results (DONE or DONE tasks), its record is kept (not overwritten with SKIPPED); a dependant that was computed from it is then stale (exit 3, e.g. disabling `optimize` after `frequencies` ran). Re-enabling it with unchanged inputs makes it and its dependants up to date.
  - **Changed fingerprint:** a stage that is DONE or RUNNING, **or that has any DONE task**, raises `StaleStageError`, which tells the user to run `--rerun-from STAGE`. Only stages with no finished task are reset automatically.
  - **`--rerun-from`:** moves the old stage directories to `.gqteashmd/superseded/`, never deleting them. It first terminates orphaned workers.
  - **Retries:** a crash or a retryable error is retried while `attempts < max_attempts`. An interrupted task is not counted as an attempt.
  - **Stage failure:** a stage fails when `failed/total > max_failed_fraction`. Any exception inside a stage marks it FAILED.
  - **Restart:** tasks left RUNNING by a dead controller are reconciled. A task with an ok `result.json` becomes DONE; otherwise its orphan is killed (verified via `/proc/<pid>/cmdline`) and the task is requeued.
  - **`--rerun-from`** is applied once per orchestrator (`self.rerun_from` is cleared after use). The hint printed for a stale stage is shell-quoted. A fingerprint input that is not JSON-serializable raises `ProjectError`.
  - **Pause:** after a stage listed in `workflow.pause_after` completes **in this run** and is not the last stage, `RunSummary.paused_after` is set, the loop stops and the CLI prints a message and exits 5 (`EXIT_STOPPED`). A rerun continues, because that stage is then up to date. A skipped or up-to-date stage never pauses. Unknown names in `pause_after` and in `[resources.stages]` are a `ConfigError` raised by `check_stage_names` (`stages/pipeline.py`), which both `Orchestrator.__init__` and `validate` call. `check_stage_inputs` (also in `stages/pipeline.py`, called by `validate` and `Orchestrator.__init__`) raises a `ConfigError` for every **enabled** stage whose `config_sections` entry is `None` in the config (e.g. `[electronic]`; `Stage 'optimize' needs an [electronic] section ...`, all joined by `; `).
- **Config** (`config/schema.py`): `[resources]` requires `total_cores` and `total_memory_mb`. A model validator checks `max_parallel_tasks × threads_per_task ≤ total_cores` and `max_parallel_tasks × memory_mb_per_task ≤ total_memory_mb` for the global values and for every stage override (merged with the global values); the message shows the factors (`3 × 2 = 6 exceeds total_cores = 4`). The keys of `[resources.stages]` must be safe stage names (`is_safe_name`). `execution.min_free_disk_mb` (default 1000) and `[workflow] pause_after` also live here. `loader.py` expands `~` (an unknown `~user` is a `ConfigError`) and resolves relative paths against the input file's directory. `[electronic]` (`ElectronicSection`, with the optional `CasscfSection` as `[electronic.casscf]`) is in the schema since P3a: `method` casscf|tda|tddft, `basis`, `functional` (required for tda/tddft, forbidden for casscf; `"hf"` gives CIS/TDHF), `singlets` (**includes S0**, O19), `triplets` (must be 0), `grid_level` (3), `scf_conv_tol`, `scf_max_cycle`, `td_conv_tol`, `overlap_norm_kept` (0.9999, 0.9 < x <= 1); casscf: `ncas`, `nelecas` (even, <= 2 ncas), `conv_tol`, `conv_tol_grad`. A present `[electronic]` requires `molecule.multiplicity = 1`. **P4 sections:** `[optimize]` (`enabled` true, `max_steps` 100, `convergence` one of GAU (default), GAU_LOOSE, GAU_TIGHT, GAU_VERYTIGHT, NWCHEM_LOOSE, TURBOMOLE, INTERFRAG_TIGHT) and `[frequencies]` (`method` auto|analytic|finite_difference, `fd_step_bohr` 0.005 with 0 < h <= 0.1, `imaginary_cutoff_cm1` 20, >= 0), both optional with defaults; `frequencies.method = "analytic"` with casscf is rejected. The cross-field validator reports **every** violation at once, joined by `; `. **P5:** `[sampling]` (`n_samples` 200, `temperature_K` 0, `low_frequency_cutoff_cm1` 10). **P6 sections** (both optional, with defaults): `[excitations]` (`include_reference` true, `samples_per_task` 1 (>= 1), `max_failed_fraction` 0.05 (0 <= x < 1), `broadening_fwhm_eV` 0.1 (> 0), `spectrum_step_eV` 0.01 (> 0)) and `[selection]` (`mode` bright|fixed, `weighting` f_over_dE2|f (default f_over_dE2), `states` (excited singlet labels, upper-cased; S0, triplets, duplicates and an empty list are rejected), `energy_window_eV` (`[lo, hi]`, 0 <= lo < hi), `n_trajectories` 100, `allow_fewer` false). The cross-field validator also reports `selection.states` that do not exist with `[electronic] singlets`, and `fixed` without exactly one state. The later sections (`[dynamics]`, `[analysis]`) arrive with P7-P8.
- **Preflight** (`preflight.py:run_preflight`): runs from `Orchestrator.preflight()` (called by `cli._cmd_run`; the result is cached, so `run()` does not repeat it), **before** the lock and `layout.ensure()`.
  - It raises `ConfigError` for: a project directory on a Windows drive in WSL (`/mnt/<letter>/`; `/mnt/data` is fine) or under a OneDrive folder; a project directory that exists as a file, or whose nearest existing parent is not a writable directory; free disk below `min_free_disk_mb` or a failed disk query (`min_free_disk_mb = 0` skips the query); a missing `required_modules` entry of an enabled stage, or one older than its minimum: entries accept `"name>=X.Y"` and the version comes from `importlib.metadata` (unreadable: skipped). `optimize` needs `pyscf>=2.6`, `geometric>=1.0`; `frequencies` needs `pyscf>=2.6`, `h5py>=3.9`; `sampling` and `selection` need `h5py>=3.9`; `excitations` needs `pyscf>=2.6`, `h5py>=3.9`. **Scratch ruling:** PySCF scratch is `task_dir/scratch` inside the project, so the existing project-directory writability check covers it; there is no separate scratch preflight.
  - It only returns a **warning** (D17) when `total_cores` or `total_memory_mb` exceeds the detected machine (`detect_machine()`: `sched_getaffinity` and `/proc/meminfo`). The CLI logs warnings after logging is configured, so they reach the console and the log file. As a backstop, `cli._cmd_run` turns an `OSError` from `session()` (lock file, `layout.ensure()`) or `configure_logging` into a `ConfigError`.
  - The location check is on the path text. A relative path is resolved (symlinks followed) against the input file's directory; an absolute path is taken as written, so a symlink in it is not followed.
- **Provenance** (`project/provenance.py`): each `run` appends one record to `.gqteashmd/provenance.json`, once the controller holds the lock (`session()`) and has opened `state.db` (so a run later refused by `StaleStageError` has a record; a run refused by preflight, the lock or a corrupt `state.db` has none) (`started_at`, `gqteashmd`, `git_commit`, `git_dirty`, `python`, `platform`, `hostname`, `cpu_count`, `cpu_model` (first `model name` of `/proc/cpuinfo`, else `null`), `packages`). `git_commit`/`git_dirty` are `null` unless gqteashmd runs from a git checkout (an editable install). A damaged file (invalid JSON, non-UTF-8 bytes, or `runs` not a list) is replaced by a fresh list.
- **State** (`project/state.py`): `StateStore(db_path, *, readonly=False)`. A failure to open or read the database at start-up (a `sqlite3.DatabaseError`, including a db path that is a directory) becomes `ProjectError` ("unreadable or corrupt", exit 3; the advice is to move the project's `.gqteashmd` directory aside, and stage results are then recomputed). Every public query method is wrapped by `_guarded`: a `sqlite3.Error` at query time becomes `ProjectError` ("The state database … failed during <method>: …", exit 3, advice: check disk space and that no other program has the database open); `close` is unguarded. `status` opens the db read-only (`mode=ro`) and never writes.
- **Lock** (`project/lock.py`): `ProjectLock` tries `flock` twice, 0.2 s apart (`locked_by` probes the same lock briefly). The error reads "pid unknown" when the holder's PID cannot be read. The file handle is closed on every failure path; an `OSError` other than "locked" (e.g. a filesystem without `flock`) becomes `ProjectError` "File locking is not available for …".
- **Logging** (`logging_setup.py`): `configure_logging` is called by `run` after the lock is held and the project directory exists; `close_logging` (in `cli.main`'s `finally`) closes all handlers and returns to a `NullHandler`. Records logged with `extra=FILE_ONLY` go to `logs/gqteashmd.log` but not to the console. `cli.main` uses it for errors and tracebacks, so each error is printed **once** on stderr (`gqteashmd: error: <message>`) with no traceback.
- **Errors** (`errors.py`):
  - Exit codes: `ShmdError` 1, `ConfigError` 2, `ProjectError` 3 (`StaleStageError` is a subclass), `StageFailedError` 4. Stopped by the user **or paused for review** is 5 (`cli.EXIT_STOPPED`).
  - `TaskError(msg, retryable=...)` is raised inside tasks; it pickles correctly (`__reduce__`).
  - **Ctrl-C** anywhere in `cli.main` (also while parsing arguments) prints `gqteashmd: interrupted` and exits 5.
  - Every error reaches the user as `gqteashmd: error: <message>`.
  - `.` and `..` are not safe stage or task names (`is_safe_name`). The XYZ parser rejects non-finite coordinates; `validate` also requires the geometry to be a regular file.
- **Testing seam:** `gqteashmd.testing.fake_stages` provides fake stages whose behaviour is set by the environment variable `GQTEASHMD_FAKE_BEHAVIOUR` (JSON). The keys are `sleep`, `fail`, `unexpected`, `crash_once`, `retryable_once`, `plan_raises`, `bad_fingerprint`, `requires` (stage name to required modules) and `skip_optimize`. The CLI's hidden `--pipeline` option selects them in tests. `gqteashmd.testing.pipelines:prepare_only` is a real one-stage pipeline for tests that must run without PySCF; `gqteashmd.testing.pipelines:canned_selection` is a canned `excitations` stage (fixed `excitations.h5`) followed by the real `selection` stage, for orchestrator-level selection tests (O20 rerun path).
- **The production pipeline** (`stages/registry.py:default_pipeline`) is `prepare → optimize (optional) → frequencies → sampling → excitations → selection`. `gqteashmd single-point INPUT [--json F] [--log F]` runs `PySCFBackend` once outside the pipeline (no project directory, no preflight): exit 0, 2 (input) or 4 (calculation failed). Its table and JSON schema are in USER_MANUAL.md §5.3.

## Key decisions (full list in master plan §10)
- **Python core.** Electronic structure dominates the cost, so the core is plain Python (D1).
- **PySCF only first.** PySCF is the only backend in the first release; ORCA, Gaussian, OpenMolcas and OpenQP come later behind the same backend contract (D4).
- **Single workstation.** The resumable controller runs one subprocess per task, with no scheduler (D5).
- **Strict input file.** One strict TOML input. Units go in key names (`dt_fs`, `temperature_K`, ...), and state labels are `S0`, `S1`, `T1` (0-based internally) (D7, D13).
- **Hardware from the user.** The user enters the hardware in `[resources]`. The program warns, without stopping, when the values exceed the detected machine (D17, implemented in P2).
- **Naming.** The package and command are `gqteashmd`; internal class names keep the `Shmd` prefix (D18).
- **P3 validation target.** Ethylene (`C:\AJCamargo\TOPICOS\Eteno\Eteno.xyz` → `tests/data/ethylene.xyz`) at SA2-CASSCF(2,2)/6-31G\* first, then TDA (D19). Done in P3a: it matches SHARC 4.1 to 1.4e-8 Eh (energies) and 1.4e-8 Eh/bohr (gradients), the dipole to 4.5e-7 e a0 up to sign; finite-difference gradient checks 1.8e-7 (CASSCF) and 5.7e-8 (TDA-B3LYP, grid_level 5) Eh/bohr.
- **O18 resolved:** `pyscf=2.14.*` pinned in `environment.yml`; runtime `pyscf>=2.6`. **O19 resolved:** `singlets` includes S0 (owner decision 2026-11-07).
- **O5 resolved (P4):** most-abundant-isotope masses in amu (`chem/masses.py`, H-Rn); reduced masses in the Gaussian/PySCF convention `mu = 1/sum(l^2/m)` (H2 stretch 1.0078 amu, not m/2). P5 sampling must use the same masses.
- **O4 resolved (P5, owner decisions 2026-11-08):** (1) T > 0 uses the exact harmonic thermal Wigner function, `sigma_Q^2 = coth(w/2kT)/(2w)`, `sigma_P^2 = w coth(w/2kT)/2` (hbar = 1, a.u.), which is the ground-state distribution at T = 0. (2) Modes with `nu < low_frequency_cutoff_cm1` (default 10 cm^-1, must be > 0), including the small imaginary modes kept by `frequencies`, are not sampled (equilibrium coordinate, zero velocity) and are listed in a warning and in `samples.json`. Linear and angular momentum are removed at each sample without rescaling. SHARC's `Ekin` line in `initconds` is the kinetic energy *before* its momentum removal (differs from the energy of its printed velocities by up to 6.4e-4 Eh), so compare pre-with-pre and post-with-post.
- **O3 and O20 resolved (P6, owner decisions 2026-11-08):** (1) bright selection accepts a candidate with probability `w/w_max` (w_max over the candidates, the window applied first and inclusive), with `weighting = "f_over_dE2"` (default; SHARC `excite.py`-compatible, **measured** in the P6 final fix wave by maximum likelihood on SHARC's black-box per-pair selections, `w = f^a dE^k`: k = -1.989 ± 0.050 (constant f = 0.1, dE ~ U(2, 10) eV, N = 3000, 598 selected), a = 0.993 ± 0.028 (constant dE = 5 eV, f ~ U(0.01, 0.4), 1527 selected); the window maximum, not the all-pairs maximum, normalises (SHARC [370, 699] vs f/dE^2 window-max z = (+1.19, +2.36), all-pairs max z = (+22.4, +32.8)); ours [353, 666], KS p = 0.96) or `"f"`; no paper is cited for f/dE^2. (2) Fewer trajectories than requested stop the stage with advice; `allow_fewer = true` (finalize-only, not fingerprinted) accepts them with a warning on a plain rerun; zero is always an error. (3) The spectrum is CSV only (no PNG). (4) Validation is black-box: energies vs `SHARC_PYSCF.py` (water CAS(4,4)/STO-3G: dE <= 8.7e-8 Eh, |mu| <= 1.2e-7, f <= 7.4e-9) and selection vs `excite.py`; our SHARC-format writers are read back by `excite.py` to 1.4e-7 eV (dE) and 1.4e-8 (f). Details: USER_MANUAL.md §8.9.
- **P7a split and O6 resolved (P7a-1, owner decisions 2026-11-08).** (1) P7a is split: **P7a-1** (this: the core on analytic models, `model-dynamics`) and **P7a-2** (LVC model, overlap-based local diabatization, triplet spin expansion, SOC with the diagonal representation and gradient corrections, `eselect`, SHARC LVC comparisons). (2) O6 options: hopping `sharc` (default) / `fssh` / `none`; `ekin_correction` `parallel_vel` (default) / `parallel_nac`; `frustrated` `keep` (default) / `reflect` (reflection reverses the momentum component along `u` in the mass-weighted metric); `decoherence` `edc` (default, C = 0.1 Eh) / `none`; `edc_convention` `sharc` (default; SHARC manual 8.7.1 eq. 8.25) / `granucci_persico` (as reproduced in Runeson arXiv:2507.18381 Sec. III.3 eqs. 44-45, citing Granucci & Persico JCP 126, 134114 (2007)); `substep_interpolation` `midpoint` (default) / `endpoint` (SHARC manual scheme); velocity Verlet with a fixed step; `nacdr` coupling only. Deferred: A-FSSH, NPI, GFSH, `parallel_diff`, thermostats.
